# Decisions

Engineering calls made without the owner, newest last. Each has a reason so it can be revisited.

| # | Date | Decision | Reason |
|---|---|---|---|
| 1 | 2026-11-14 | pnpm 10.34.6 (already on PATH), pinned via `packageManager`. | Available without any global install. |
| 2 | 2026-11-14 | TypeScript pinned to the newest 6.0.x, not 7.0.2 (npm `latest`). | `typescript-eslint` 8.72.2 declares `typescript >=4.8.4 <6.1.0`; TS 7 (the native port) is not supported by the lint toolchain yet. |
| 3 | 2026-11-14 | Pinned: three 0.187.0, @mediapipe/tasks-vision 1.2.3, @dimforge/rapier3d-compat 0.21.0, vite 8.3.8, vitest 5.1.0, eslint 10.15.0, @playwright/test 1.65.1. | Current stable on npm at kickoff; exact pins as required. |
| 4 | 2026-11-14 | MediaPipe WASM and `.task` models are **not committed**. `pnpm setup:assets` copies WASM from `node_modules` into `public/wasm/tasks-vision-<version>/` and downloads models (version `1` URLs, not `latest`) into `public/models/`. Both directories are gitignored. | About 35 MB of binaries would bloat git history; the script is deterministic and the paths are versioned for immutable caching. Deploys run the script before `pnpm build`. |
| 5 | 2026-11-14 | `Claude outputs/` (the kickoff brief) is gitignored, not committed and not modified. | It is the owner's planning file; its content now lives in `docs/`. Remove the ignore line to commit it. |
| 6 | 2026-11-14 | Custom subagent types (`builder`, `helper`, `reviewer`) were created in `.claude/agents/` but are not loadable until the session restarts, so tonight's subagents are general-purpose agents with the model set explicitly (sonnet, haiku, opus) and the role text in the prompt. | As instructed in the brief. |
| 7 | 2026-11-14 | The orchestrator writes the shared contract files (`src/tracking/types.ts`, `src/input/types.ts`, `src/core/sport.ts`) itself. They contain only type declarations and constants. | Interfaces must be decided by the orchestrator and committed before parallel builders start; writing them once as files is cheaper and more exact than repeating them in every brief. |
| 8 | 2026-11-14 | `noUncheckedIndexedAccess` is off. | The landmark path is typed-array index arithmetic; the flag would force `!` on every read with no safety gain. |
| 9 | 2026-11-14 | Landmark coordinates are mirrored once, in the tracking layer. Everything downstream (filters, recognizers, recordings, synthetic scripts) works in mirrored display space; landmark indices keep their anatomical meaning. The avatar is viewed from behind. | One convention, applied in one place; "player's left hand moves the on-screen left hand" then needs no further flips. |
| 10 | 2026-11-14 | One time base, "game ms". Camera frames are stamped from `requestVideoFrameCallback` metadata (`captureTime`, falling back to `presentationTime`), which is on the `performance.now()` timeline. Synthetic and replay sources are stepped by the game clock. | Camera-clock timestamps as required, directly comparable with game time for latency compensation, and `?timeScale` can speed up headless checks. |
| 11 | 2026-11-14 | Continuous signals (hand hold position, lean, knee-lift cadence) are exposed as in-place state on `InputProvider.state`; only discrete moments are events. | The brief lists `HandHold`, `Lean` and `KneeLiftCadence` as events, but emitting them every frame would allocate per frame. Same information, no garbage. |
| 12 | 2026-11-14 | Debug input (`?input=debug`) is a second `InputProvider` implementation, not a fake landmark source. | It must produce the same events and state the recognizers produce; skipping landmarks keeps it simple and deterministic. The synthetic player covers the landmark-to-recognizer path. |
| 13 | 2026-11-14 | `?renderer=webgl` selects `WebGPURenderer` with `forceWebGL: true` (its WebGL2 backend), not the legacy `WebGLRenderer`. | The legacy renderer needs the classic `three` build and classic materials; shipping both would duplicate three.js and every material. The switch still answers the real question (does the renderer contend with MediaPipe less on WebGPU or on WebGL2). |
| 14 | 2026-11-14 | Milestone 1 builders run in parallel in one working tree on disjoint directories, each checking only its own directory; the orchestrator runs the full checks before each commit. | Simpler than worktrees for four tasks with no shared files; contracts were committed first. |
| 15 | 2026-11-14 | Headless rounds are played by a per-sport bot (`Sport.createBot()`), not by fixed scripts. The shell asks the bot for the next moves whenever the synthetic player's move queue is empty. | A fixed script cannot react to game state (which hold is next, whether the pins have settled, how close the foul line is). The bot still goes through the full landmark, filter and recognizer path. |
| 16 | 2026-11-14 | Gesture events are queued and delivered in timestamp order from `InputProvider.update()`, once per rendered frame, never from inside a camera callback. | Sports get deterministic ordering inside the game loop. Costs at most one render frame of delay; each event still carries the true time of the moment. |
| 17 | 2026-11-14 | Throw, swing and punch recognizers measure wrist speed relative to the shoulder, and the throw recognizer suspends while the shoulders move faster than `maxBodySpeed`. | With image-space speed, a sidestep or squat looked like a 10 sw/s throw. |
| 18 | 2026-11-14 | Recognizer thresholds were retuned from the brief's starting points to fit the synthetic player after filtering (for example throw `minPeak` 2.5 sw/s, `startSpeed` 2.0, and a two-frame lag correction on peak times). All are placeholders until real recordings exist. | Filter lag attenuates peak speeds; the starting values never fired on soft throws. |
| 19 | 2026-11-14 | The device gate treats tracking as "sustains N Hz" when the tracker completes N back-to-back inferences per second on a synthetic frame (capped at 30), measured while a representative scene renders. | The gate runs before camera permission, so it cannot use the camera. |
| 20 | 2026-11-14 | `?short=1` plays a shortened round in every sport (two bowling frames, three pitches, two arrows, one javelin attempt, a 25 second climb). | Headless checks finish in reasonable time, and it is handy for quick tries. |
| 21 | 2026-11-14 | Climbing stamina drain was lowered from the first values (two hands 0.035 to 0.02 per second, one hand 0.06 to 0.035). | The bot ran out of stamina near 11 m, so the first rest ledge at 20 m was unreachable. To be judged by playtest. |
| 22 | 2026-11-14 | Bowling's default `hookGain` was lowered from 1.2 to 0.35. | The synthetic swing saturated the hook on every ball; real wrist-path curvature is unknown, and a ball that always hooks into the gutter would be a bad first impression. |
| 23 | 2026-11-14 | Javelin: crossing the foul line is called only after 0.45 s with no throw (`crossGraceS`), and a throw is back-dated to its release time. | Throw events arrive 170 to 300 ms after the wrist-speed peak; without the grace, a legal release just before the line was called a foul. |
| 24 | 2026-11-14 | Javelin's release angle is a proxy: the upward share of the wrist's 2D velocity at release, mapped onto 12 to 52 degrees. | The player throws into the screen, the axis the camera measures worst, so true loft is not observable. |
| 25 | 2026-11-14 | Batting judges a swing by the swing-start event's own timestamp plus `batTravelMs` (130), and resolves a pitch up to 250 ms after the ball has passed. | The tracker reports a swing late; judging by arrival time would make every swing late. This is the game's latency compensation. |
| 26 | 2026-11-14 | Archery has a fallback for players whose fist the tracker cannot see: auto-nock after 6 s with hands together, release on a quick move toward the bow hand or a 2.5 s hold. | Hand crops at distance are the least proven part of the pipeline; the sport should be playable on day one regardless. Bowling has an equivalent hold-still pick-up. |
| 27 | 2026-11-14 | The hand cursor is disabled for synthetic and replay sources, and for real players it cannot begin a dwell for 1.2 s after a screen appears or until the hand has been outside every button. | A hand resting where a button appears pressed "Play again" by itself. |
| 28 | 2026-11-14 | The production CSP is stricter than the starting point: no `blob:` anywhere, no inline styles. `vite preview` sends the same headers, so every Playwright suite runs under the production policy. | Each removal was proven by the browser suite passing with zero violations. |
| 29 | 2026-11-14 | Sports ran in parallel in one working tree with per-sport build directories and ports (`playwright.sport.config.ts`), not git worktrees. | Worktrees would each need their own `node_modules`, Chromium download and model files; disjoint directories gave the same isolation for free. |
| 30 | 2026-11-14 | Baseball batting's accent is lavender `#B8A6E6`; the pitcher is a second headless athlete in teal. | The brief gave accents for four venues; batting needed one. |
| 31 | 2026-11-14 | Archery measures the draw from the distance between the two wrists with one small helper, `wristDistanceRawException` in `src/sports/archery/aim.ts`, which reads pose landmarks 15 and 16. This is the single documented exception to "sports never read raw landmarks". | The same distance from `state.arms.*.wristX/wristY` needs the shoulder-to-shoulder vector, which `InputState` only gives as a length; assuming level shoulders is wrong by about the tilt angle in radians, and a raised bow arm tilts them well past the 0.05 sw that the draw curve tolerates. Revisit by adding a shoulder vector to `InputState`. |
| 32 | 2026-11-14 | `SportHost` disposes the whole stage with `disposeObjectTree` at the end of every round, as a safety net on top of each sport's own `dispose`. Session-long shared materials and geometries are marked with `markShared` and skipped. | three.js keeps a render object per mesh alive through its material's listener list until the mesh itself is disposed; with shared materials that leaked about 1 MB per round. A host-level net also covers sports that forget something. |
| 33 | 2026-11-14 | Baseball pitching was built as a sixth sport after the milestones were complete: fist or open hand picks fastball or curve, an overarm throw at a lit cell of a 3x3 zone, speed scored only up to 95 km/h. | The brief listed it as the next thing to build once everything else was done. The speed cap is the brief's "cap the effort that scores". |
| 34 | 2026-11-14 | The device gate is a warning, not a block. A failed check shows "This device may struggle" with "Play anyway"; only missing WebGL2 or Web Workers is terminal. Thresholds dropped to 15 Hz tracking capacity and 27 fps, with a marginal band (20 Hz, 40 fps) that passes silently. | Allen's laptop failed the old gate (25 Hz, 50 fps) while playing every sport well, and he asked for a warning instead. The old tracking figure also included frame-copy and worker overhead rather than inference capacity. |
| 35 | 2026-11-14 | Javelin uses no hand state at all: the javelin follows the dominant hand, the run starts by itself, and the throw is the shared `ThrowReleased` event gated on wrist above shoulder and a speed guard that rises with run speed. Run speed contributes about 36% of the variable release speed. | Allen found the overhead fist unreliable and unnecessary, and wanted faster running to be rewarded. |
| 36 | 2026-11-14 | The batter is posed side-on by animation (stance, contact, follow-through keyed to the swing event) instead of mirroring the player's arms. Right-handers stand on screen left of the plate. | A mirrored front-on pose cannot look like a side-on batting stance; Allen reported the side and facing as wrong. |
| 37 | 2026-11-14 | Bowling and pitching launch with the continuously displayed aim (smoothed, frozen at swing or wind-up) rather than an aim computed only at release. Bowling `aimGain` 0.09 to 0.025 and `maxAngle` 0.1 to 0.045. | The aim indicator has to predict the throw honestly, and the old bowling gain reached the gutter from a small hand movement. |
| 38 | 2026-11-14 | Climbing with mouse uses an opt-in click mode on `DebugInput`: a click on a hold is a sticky grab and switches the mouse to the other hand. Javelin reuses the click count for click-to-throw. Other sports keep the old hold-to-close behaviour. | Allen could not climb with the mouse because releasing the button released the hold. |
| 39 | 2026-11-14 | Pitching keeps fist (fastball) or open hand (curve) as the pitch choice, now untimed and after a catcher's call. | It is a slow, deliberate moment, which the kinematics rule allows. Flagged to Allen as a candidate to change if fist detection misreads for him. |
| 40 | 2026-11-15 | Camera-off mode (`?input=debug`) is mouse only. `DebugInput` exposes a programmatic `MouseControl` API (`asMouseControl`), each sport builds a one-button scheme on it, and keyboard game controls are removed. Escape, H and Enter stay as UI keys. Mouse schemes favour ease over fidelity (fixed speeds, no hook or stepping in bowling, automatic bat height). | Allen: the games are meant for the camera; the mouse is only an option to try them and must need nothing but the mouse. |
| 41 | 2026-11-15 | The bowling count waits for wobbling standing pins and for moving pins or the ball near a standing pin, adds settling damping, and freezes pin states at the count (`commitRoll`) so the next rack matches the score. The cap is 6 s as a last resort. | Allen saw 9 pins fall and 8 scored. Correctness of the count beats a fast verdict; median is still 1.32 s. |
| 42 | 2026-11-15 | Batting scores in feet with the fence at 350 ft, by scaling the whole flight model by 1.4224 (lengths by S, speeds and times by sqrt S, drag by 1/S). The wall keeps its 1.2 m height, so a home run needs about 358 ft. Bests moved to a new `scoreKey` (`batting-ft`). | Allen asked for 350 ft at proportionally the same difficulty; uniform scaling keeps the set of home-run swings identical. |
| 43 | 2026-11-15 | Running in place is detected by fusing arm pump, thigh foreshortening, foot lift and torso bob, with no use of world-z. | A front-on camera barely sees knees lifting toward it, so the knee-only detector missed real runners. |
| 44 | 2026-11-15 | `SportMeta.usesHandedness` (default true) controls the dominant-hand toggle and the handedness calibration step; climbing sets it false. | Allen: dominant hand means nothing in rock climbing. |
| 45 | 2026-11-15 | Climbing with the mouse: grabbing a new hold frees the other hand, the pointer is unprojected through the camera onto the wall, and one-hand stamina drain is scaled by 0.6 in mouse play. Replaces the mouse part of 38. | Allen: the held hand stopped the pull, and the cursor did not match what was grabbed (it was read as a hand position in a reach box). The mouse always hangs from one hand, so unscaled drain emptied stamina in about 28 s. |
| 46 | 2026-11-15 | Left/right mix-ups are corrected in two places: hand slots weigh staleness and swap back after 12 frames in the wrong order; the pose side guard undoes only sudden exchanges between consecutive frames, never by shoulder order. | Allen saw arms flip in climbing, traced to a returning hand taking the wrong slot. An absolute shoulder-order rule would have "corrected" real side-on turns in pitching and javelin and fired false throws. |
| 47 | 2026-11-15 | "Turn camera on" reloads the page without `input=debug` instead of swapping the input provider in place. The camera hand cursor is suspended during active play in every sport. | The shell's screen chains are bound to the current input, and the reload path is the one already tested end to end. Allen: the cursor could click buttons mid-climb. |
| 48 | 2026-11-15 | Archery never shoots on tracking loss: release needs a confirmed open hand or a plausible fast wrist collapse with both wrists clearly visible; lost wrists hold the draw then let down without a shot. | Allen: hands going out of sight fired the arrow. At full draw the draw hand is beside the face, so loss there is the normal case. |
| 49 | 2026-11-15 | Camera pitching is aimed by the glove hand; the ring locks while the throwing wrist is fast; the throw sets speed and steers by at most 0.15 m. Replaces the pitching part of 37. | Allen's decision after finding the one-hand aim awkward: the ring was placed by one rule and moved by another during the throw. |
| 50 | 2026-11-15 | `state.shoulderWidth` is a stable body scale: the larger of the live shoulder width and 0.8 x a learned shoulder-to-torso ratio x torso length. The ratio is the median of recent square-on frames, seeded by calibration. Tracking needs the near shoulder at 0.5 visibility and the far one at 0.2. | Allen's side-on batting swings did nothing: in profile the live shoulder width collapses, so every speed in shoulder widths was meaningless and the far shoulder made the player "not tracked". Torso length does not change when the body turns. |
| 51 | 2026-11-15 | Swings are read from the wrist midpoint or the one visible wrist, announced after a short confirmation at 4 sw/s but stamped at the true onset, with the forward direction taken from handedness (backward motion counts only at 1.8 x). Javelin accepts a throw whose wrist went over the shoulder at any point, raises its speed floor to 6 sw/s, refuses mostly upward motions and lets a stronger release supersede a weak one inside the cooldown. | Loosening detection for real side-on motion opened false triggers (waggle, wind-up, arm pump, cocking the arm), found by review; these guards close them. The direction rule is a guess until real recordings exist. |
| 52 | 2026-11-15 | A motion that was seen but refused leaves an optional `InputState.rejected` note; batting and javelin show it as a plain-word hint. | A player could not tell "not seen" from "too slow". |
| 53 | 2026-11-15 | Camera hand cursors: one per tracked hand, selection only by closing a fist over a button (250 ms confirm, hand seen open there first); dwell-to-select is removed. Hand crops therefore run in the lobby and on in-round overlays, loaded in the background; adding hand crops no longer pauses pose frames. Replaces the dwell part of 27. | Allen: the single cursor jumped between hands, and an open hand should never select. Blocking the menu on the hand model made startup slower and broke the camera-path test. |
| 54 | 2026-11-15 | Tutorials are optional and per sport: `SportMeta.hasTutorial`, `SportContext.tutorial`, `coach` and `finishTutorial()`, a shared `TutorialRunner`, a Tutorial button on the start screen, nothing saved. | Allen: every game should have a tutorial the player can choose, never a forced one. |
| 55 | 2026-11-15 | Local multiplayer will be pass-and-play only: up to 4 players, typed names, one player on camera at a time, turns by natural unit, no bests saved. No simultaneous play and no pitcher-against-batter mode. | Allen's decision. Two tracked bodies would double tracking cost on a laptop that already trips the device warning and risk identity swaps. |
| 56 | 2026-11-15 | The site's address is `headlesssports.allenzheng.com` (was `sports.allenzheng.com`). The route in `wrangler.jsonc` stays commented until a first deploy is smoke-tested. | Allen's choice of subdomain; the zone is on Cloudflare. Allen deploys later, by hand. |
| 57 | 2026-11-15 | End-to-end tests that play a whole round in real time carry their own `test.setTimeout` at about 2.5 x their isolated duration; the global 60 s limit is unchanged. | Mouse rounds cannot use `timeScale`, and several sat at 50 to 58 s, so a different one timed out on each full run. |
| 58 | 2026-11-16 | Multiplayer is built on a `Turns` service in `SportContext` (`handOver`, `setStanding`, `handednessOf`) plus `finishMulti`; the sport owns turn order and per-seat state, the shell owns players, names, per-seat calibration, the handover card, standings and the ranked table. `ctx.calibration` is a getter that follows the seat. | Turn units differ per sport (frame, arrow, attempt, set, whole climb), so the sport must decide when a turn ends; everything else is identical across sports and belongs in one place. |
| 59 | 2026-11-16 | The camera handover continues by itself only after the frame has been empty for 0.7 s and someone has then stood still for 1 s; otherwise it waits for Ready (fist, click or Enter). The input provider is fully reset at each seat switch. | A looser rule (the person moved or changed size) let the previous player be taken for the next, crediting their turn to the wrong seat. Without the reset, a half-finished throw and the body-scale estimate carried over between people. |
| 60 | 2026-11-16 | Seeded values that affect difficulty are drawn once in the single-player order and replayed for every seat (archery wind per arrow number, batting pitches, pitching calls, the climbing wall). | Fairness between players, and single-player rounds stay identical because the draw order does not depend on the seat count. |
| 61 | 2026-11-16 | Ranking uses the score at the precision shown, with an optional `RoundResult.tieBreak` (larger ranks higher) and `unranked`. Climbing ties on height break on the faster time. Nothing from a multiplayer game is saved to scores; names and dominant hands are remembered on the device. | Ranking on hidden decimals put two players shown "3.4 m" in first and second place. "Your best" has no clear owner in a shared game. |
